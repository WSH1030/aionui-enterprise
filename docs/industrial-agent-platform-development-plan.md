# 工业智能体平台开发计划

> **给实施人员：** 本计划用于按阶段实施工业智能体平台；每个阶段完成后必须通过对应验收，再进入下一阶段。

**目标：** 在现有 AionUi 基础上建设名为 Rd Worker 的企业级工业智能体平台，提供桌面端入口、内网部署、模型调用、知识沉淀、Skill 复用、用户权限和全过程审计。

**架构：** Rd Worker（Electron 桌面端）负责交互；AionCore 负责登录、数据、项目、权限、审计和任务编排；Agent Runtime 负责调用 Aion CLI、Codex CLI 或其他受控 Agent；模型服务运行在本机或公司内网。公司部署模式采用“桌面端连接统一内网 AionCore”，同时保留单机离线开发模式。

**技术栈：** Electron、React、TypeScript、Arco Design、IPC Bridge、AionCore（Rust）、ACP/Agent Runtime、Ollama 或 vLLM、本地/内网模型、SQLite 或 AionCore 支持的服务端数据库。

**需求来源：** 用户提供的《工业智能体平台·功能梳理.md》。该文件作为业务需求和价值目标，本计划补充技术边界、阶段拆分和验收标准。

## 全局约束

- 所有企业数据、文件、对话和日志默认留在本机或公司内网，不发送到公网。
- 权限必须由 AionCore 后端强制校验，前端隐藏菜单不算安全措施。
- Agent 只能访问当前用户有权限的项目工作区，不能通过命令行、MCP 或文件接口绕过权限。
- 外部网页搜索、浏览器、外部 MCP 和公网插件同步默认关闭。
- 模型服务必须使用本地模型或企业内网模型服务；使用云端模型时必须显式配置并经过管理员批准。
- AionUi 与 AionCore 保持进程边界：渲染层不直接访问 Node.js、文件系统或后端数据库。
- 新增或修改的界面文字使用现有 i18n 机制；组件使用 Arco Design，图标使用 Icon Park。
- 先完成平台底座和一个可量化的试点场景，再扩展到其他工业业务。
- 本计划不包含当前立即制作安装包；安装包在功能稳定、权限和内网部署验证通过后处理。

## 一、目标部署形态

### 1. 公司内网版（主目标）

```text
员工电脑：Rd Worker 桌面端
              │ HTTPS/WebSocket，仅访问公司内网
              ▼
内网服务器：AionCore
              ├─ 登录、用户、部门、角色和项目权限
              ├─ 对话、文件元数据、知识库、Skill 和审计日志
              ├─ Agent Runtime：Codex CLI / Aion CLI
              └─ Ollama/vLLM 等内网模型服务
```

员工电脑只需要安装 Rd Worker。Codex CLI 和模型由服务器统一管理，避免每台电脑重复安装模型和工具。

### 2. 单机离线版（开发和小范围试用）

```text
同一台电脑：Rd Worker + AionCore + Agent Runtime + 本地模型
```

该模式适合开发验证和没有服务器条件的试用，但不作为多人统一权限管理的最终形态。

### 3. 必须明确的数据边界

- 单机模式：文件留在本机项目工作区，由本机 Agent 处理。
- 公司模式：文件进入受权限保护的内网项目工作区，或由内网文件服务提供受控访问。
- 文件不得因为调用模型而上传到外部模型厂商或公网服务。
- ERP、MES、PLM、OA 第一阶段只读接入；任何写回动作都必须经过人工确认和单独授权。

## 二、产品范围分层

### P0：平台底座

- 桌面端统一入口 Rd Worker。
- 内网 AionCore 服务连接和健康检查。
- 用户登录、退出、会话过期和管理员用户管理。
- 部门、角色、项目成员和项目工作区。
- 项目对话与全局最近对话分离。
- Agent、模型、Skill、MCP 的统一配置入口。
- 文件访问边界、操作确认和审计日志。

### P1：第一个可交付业务闭环

优先选择“企业制度/工艺知识问答”或“财务三单核销”作为试点。推荐先做制度/工艺知识问答，因为数据风险较低、规则清晰、容易验证权限隔离和答案出处。

- 文档导入、解析、版本和权限。
- 按项目/部门隔离的知识检索。
- 回答附文件名、版本和出处。
- 用户反馈、纠错和知识更新记录。
- 试点场景的效率、准确率和人工复核指标。

### P2：企业知识与 Skill 平台

- 企业知识库分层：国家/行业标准、通用方法论、企业制度与工艺。
- Skill 创建、测试、版本、发布、停用和权限。
- 内部 Skill 市场。
- 专家智能体模板和助手绑定。
- MCP 白名单、参数限制、调用日志和管理员审批。

### P3：工业业务扩展

- 投标报价和图纸/BOM 处理。
- 采购催料、供应商比价和齐套检查。
- 来料质检判定和客诉追溯。
- 会议纪要、周报、合同条款识别。
- ERP/MES/PLM/OA 只读接入。
- 企业微信、钉钉或飞书通知。

### P4：治理和规模化

- 按用户、部门、项目的用量配额。
- 模型自动路由和成本统计。
- 管理员审计台账和报表导出。
- 备份、恢复、升级和服务器监控。
- 多服务器 Agent Runner 和任务队列。

## 三、实施阶段

### 阶段 0：需求、架构和安全基线

**目标：** 在写代码前固定部署、数据和安全边界。

**工作内容：**

- 确认公司版采用统一内网 AionCore 服务器。
- 确认文件进入内网项目工作区，不走公网模型服务。
- 盘点 AionUi 当前前端、AionCore 后端和 Codex CLI 的职责边界。
- 建立 Agent Runtime 统一接口，避免业务代码直接绑定某一个 CLI。
- 验证 Codex CLI 本地模式、Ollama 和 `qwen3.5:4b` 的兼容性。
- 形成威胁模型：越权读取、越权写文件、MCP 外传、命令注入、日志泄露、模型切换绕过。
- 选择第一个试点场景和可量化指标。

**验收标准：**

- 形成架构图、数据流图、权限矩阵和部署说明。
- 明确单机版与公司内网版的差异。
- 本地模型可以在断网环境启动并完成最小对话测试。
- 未批准的公网域名、外部 MCP 和浏览器工具无法调用。

### 阶段 1：内网服务基础

**目标：** 让 Rd Worker 可以稳定连接本机或内网 AionCore。

**主要模块：**

- AionUi：后端地址配置、连接状态、断线重连和错误提示。
- AionCore：服务端启动参数、监听地址、健康检查和版本信息。
- 数据层：统一保存用户、项目、对话、文件元数据和审计记录。
- 部署层：开发环境、内网服务器环境和备份目录。

**验收标准：**

- 员工客户端只能访问配置的内网地址。
- AionCore 重启后对话、项目和权限数据不丢失。
- 服务器不监听公网网卡，或由防火墙明确拒绝公网访问。
- 客户端无法绕过 AionCore 直接读取服务器文件或数据库。

### 阶段 2：用户登录和组织权限

**目标：** 建立公司多人使用所需的身份和角色体系。

**角色：**

- 系统管理员：管理用户、部门、角色、模型、Agent、MCP 和全局策略。
- 部门管理员：管理本部门成员和部门项目。
- 项目管理员：管理项目成员、项目文件、Skill 和项目规则。
- 普通成员：访问被授权的项目和对话，按策略使用 Agent。
- 只读成员：只能查看授权内容，不能修改文件、Skill 或项目配置。

**后端规则：**

- 每个请求根据会话用户计算授权范围。
- 项目列表、对话列表、文件浏览、文件读写、Agent 执行、MCP 调用分别校验权限。
- 对话必须绑定用户或项目；“最近对话”不能成为绕过项目权限的入口。
- 管理员操作、权限变更和失败的越权请求都记录审计日志。

**验收标准：**

- 用户只能看到自己有权限的项目和对话。
- 只读成员无法写文件、执行危险命令或修改 Agent 配置。
- 删除成员、移除项目权限后，旧会话和旧链接也不能继续访问受限数据。
- 权限测试覆盖“无权限、只读、成员、项目管理员、系统管理员”五类身份。

### 阶段 3：项目、文件和对话隔离

**目标：** 让项目成为文件、对话、知识和 Skill 的安全边界。

**工作内容：**

- 项目创建、重命名、归档、成员管理和项目目录绑定。
- 项目下的对话只显示在项目区域，不进入全局最近列表。
- 最近列表只显示没有项目归属的普通对话。
- Agent 每次运行都接收后端解析后的项目工作区，不接受前端任意路径。
- 文件 API 根据项目权限过滤目录、文件和操作类型。
- 项目级规则、默认模型、可用 Skill 和 MCP 白名单独立保存。

**验收标准：**

- 同级项目之间不能看到对方的对话、文件和知识库。
- Agent 不能通过 `..`、绝对路径、符号链接或命令行参数逃逸工作区。
- 项目对话不会混入“最近”，普通对话不会错误归入项目。
- 用户退出登录后，客户端缓存不能继续展示其他用户的数据。

### 阶段 4：Agent Runtime 和本地模型

**目标：** 把 Codex CLI 接入为可替换的主 Agent Runtime，同时保持本地模型和离线能力。

**统一能力：**

```text
createSession(workspace, policy)
sendMessage(sessionId, message)
approve(requestId, decision)
cancel(sessionId)
resume(sessionId)
streamEvents(sessionId)
```

**实现顺序：**

1. 保留现有 Aion CLI 运行链路作为回退方案。
2. 验证 Codex CLI 的本地 OSS 模式：Ollama + `qwen3.5:4b`。
3. 在 AionCore 中增加 Codex Runtime 适配，不让渲染层直接拼接 Codex 命令。
4. 把模型列表、模型能力、推理级别和权限模式从后端动态返回给界面。
5. 为每个 Agent 配置允许的模型、工作区、命令权限、MCP 和网络策略。
6. 增加模型故障回退，但回退不能跨越用户权限或网络策略。

**离线安全要求：**

- Codex CLI 使用本地/内网模型时，关闭公网搜索、外部插件同步和远程服务。
- AionCore、Codex CLI、Ollama/vLLM 使用防火墙出站白名单。
- 运行前记录实际模型、Provider、工作区和权限模式。
- 模型请求失败时显示“模型服务不可用”，不能自动切换到公网模型。

**验收标准：**

- 断开公网后，仍可完成本地模型对话和受限文件操作。
- Codex Runtime 能在项目工作区中读取、修改和输出受控文件。
- 未授权的网络访问、外部 MCP 和公网模型调用被拒绝并记录。
- Aion CLI 与 Codex CLI 可以通过同一套会话、权限和审计接口工作。

### 阶段 5：知识库、Skill 和 MCP 治理

**目标：** 将一次性对话沉淀成企业可复用资产。

**知识库：**

- 文档上传、解析、分段、索引、版本和归档。
- 文档继承项目、部门或企业级权限。
- 检索结果附出处、版本和更新时间。
- 删除或降权文档后，检索索引同步失效。

**Skill：**

- 草稿、测试、发布、停用和版本回滚。
- Skill 绑定适用角色、项目和允许的工具。
- 发布前由项目管理员或系统管理员审核。
- Skill 执行记录保存输入摘要、版本、工具调用和结果状态。

**MCP：**

- 仅允许管理员登记和启用 MCP 服务。
- 每个 MCP 服务配置工具白名单、参数限制、项目范围和网络范围。
- 默认拒绝公网 MCP。
- 每次调用记录用户、项目、工具、参数摘要和结果状态。

### 阶段 6：第一个业务试点

**目标：** 用一个低风险场景验证平台能产生真实收益。

**推荐场景：企业制度/工艺知识问答。**

**交付内容：**

- 导入一批经过脱敏的制度、工艺和操作文件。
- 设置部门、项目和文档权限。
- 建立带出处的问答助手。
- 提供“答案有帮助/无帮助”和纠错入口。
- 记录响应时间、引用命中率、人工复核率和问题解决率。

**通过条件：**

- 用户不能检索无权限文件。
- 答案必须能回溯到文档和版本。
- 低置信度问题明确提示人工确认。
- 连续试运行后，业务人员每天实际使用，指标达到试点目标。

### 阶段 7：企业治理和工业场景扩展

**目标：** 在试点稳定后扩展效率和治理能力。

**顺序：**

1. 审计台账、用量配额和部门统计。
2. 会议纪要、周报和合同条款识别等低风险办公流程。
3. 财务三单核销或采购催料等规则明确的流程。
4. 报价、图纸/BOM 和质检等需要专业校验的流程。
5. ERP/MES/PLM/OA 只读接入。
6. 企业微信、钉钉或飞书通知。

每个业务场景都必须有：输入范围、输出格式、人工确认点、错误处理、权限范围、审计字段和量化收益指标。

### 阶段 8：桌面端发布和运维

**目标：** 在功能和内网安全验证通过后交付给同事使用。

**工作内容：**

- 打包 Rd Worker 桌面端，不要求员工单独安装 Codex CLI 或模型。
- 服务器安装 AionCore、Codex Runtime 和本地/内网模型。
- 配置内网地址、证书、自动更新和版本回滚。
- 提供管理员初始化、备份恢复、日志导出和故障诊断。
- 对离线单机版和内网多人版分别打包和验收。

**验收标准：**

- 新电脑安装 Rd Worker 后可以连接内网并登录。
- 员工无法通过修改客户端配置访问未授权项目。
- 服务器断网时本地模型仍可工作；服务器无公网出站请求。
- 升级失败可以回滚，数据备份可以恢复。

## 四、建议的数据对象

```text
User                 用户
Department           部门
Role                 角色
Permission           权限
Project              项目
ProjectMember        项目成员
Conversation         对话
ConversationMember    对话访问范围（必要时使用）
Workspace             项目工作区
FileAsset             文件元数据和版本
Agent                 Agent 配置
AgentRuntime          Runtime 实例和策略
ModelProvider         模型服务配置
Skill                 Skill 及版本
KnowledgeDocument     知识文档及版本
McpServer             MCP 服务及白名单
AgentRun              Agent 执行记录
UsageQuota            用量配额
AuditLog              审计日志
```

数据表和接口优先复用 AionCore 已有能力；AionUi 不自行复制一套用户、权限或对话数据库。

## 五、代码范围和仓库边界

### AionUi 仓库

- `packages/desktop/src/renderer/`：登录页、项目/对话界面、Agent/模型/Skill 配置界面。
- `packages/desktop/src/common/adapter/`：HTTP、IPC、认证、项目、权限和 Agent 请求映射。
- `packages/desktop/src/common/types/`：前后端共享的用户、项目、权限、Agent 和审计类型。
- `packages/desktop/src/process/`：桌面端启动、AionCore 连接和内置资源管理；不放业务权限判断。
- `tests/unit/`：分组、路由、权限展示、数据映射和运行状态的前端单元测试。

### AionCore 仓库

- 负责认证、会话、用户、角色、项目、对话、文件、审计和配额的真实校验。
- 负责 Agent Runtime 的进程生命周期、工作区限制、模型策略和 MCP 策略。
- 负责 Codex CLI、Aion CLI 和本地模型服务的后端适配。
- 负责服务端数据库、迁移、备份和内网部署。
- 负责 Rust 单元测试、API 测试和运行器安全测试。

AionUi 当前通过本地或打包的 `aioncore` 二进制连接后端；因此登录、权限、数据隔离和 Codex 本地模型支持不能只改 AionUi 前端。

## 六、测试和发布门禁

### 功能测试

- 登录、退出、会话过期和密码策略。
- 五种角色的项目、对话、文件、Agent、Skill 和 MCP 权限矩阵。
- 新建项目、项目对话、最近对话和跨项目访问。
- 文件读、写、移动、删除和路径逃逸。
- Codex/Aion CLI 的会话、取消、恢复、审批和错误恢复。
- 知识库版本、权限继承和引用出处。

### 安全测试

- 关闭公网后的完整工作流测试。
- DNS、HTTP、HTTPS、WebSocket 出站检查。
- 外部 MCP、浏览器和插件同步禁用测试。
- 修改客户端请求、伪造项目 ID、伪造文件路径和重放旧会话测试。
- 审计日志不能包含 API Key、密码、完整敏感文件内容或未脱敏凭据。

### 质量门禁

- TypeScript 类型检查通过。
- 受影响的 Vitest 单元测试通过。
- 渲染层改动通过 i18n 类型和 i18n 完整性检查。
- `git diff --check` 通过。
- 业务试点必须有实际用户和量化结果，不以“界面能打开”作为上线标准。

## 七、明确暂不做的内容

- 暂不把 Codex CLI 和模型打进安装包。
- 暂不接入公网模型作为默认路径。
- 暂不允许 Agent 自动写回 ERP、MES、PLM 或 OA。
- 暂不一次性开发全部报价、采购、质检和图纸场景。
- 暂不让前端承担登录、权限或数据过滤的最终责任。
- 暂不建设面向公网的 SaaS 多租户系统。

## 八、首轮实施顺序

```text
需求/安全基线
      ↓
内网 AionCore 连接
      ↓
```
